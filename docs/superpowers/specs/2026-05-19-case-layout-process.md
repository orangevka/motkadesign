# Процесс верстки кейса портфолио
> Дата: 2026-05-19 | Статус: рабочий стандарт

Цель: верстка нового кейса за полдня вместо двух, без циклов правок из-за неясности.

---

## Роли

| Кто | Что делает |
|-----|-----------|
| **Дизайнер** | Готовит Figma, согласует карту, принимает секции визуально |
| **Claude** | Читает Figma, пишет карту, генерирует код, делает скриншоты |
| **Точка синхронизации** | Карта перед стартом, скриншот после каждой секции |

---

## Этапы

### Этап 0 — Figma Аудит *(обязательный, до любого кода)*

**Кто:** Claude читает макет через Figma MCP.

**Что делает Claude:**
1. Читает структуру страницы — список всех секций сверху вниз
2. Для каждой секции определяет:
   - Какой готовый компонент использовать (`_nav-light.html`, `_footer.html`, `_popup.html`, case-teasers)
   - Какие CSS-классы из `styles.css` / shared CSS уже подходят
   - Какие новые классы нужно создать (с CSS-префиксом кейса, например `sp-` для Spherum)
3. Выявляет риски:
   - Абсолютно позиционированные декоративные элементы (тени, маскоты, текстуры)
   - `mix-blend-mode` — требует осторожности со stacking context
   - Нестандартные шрифты — проверить есть ли в Factor A / Spectral / Montserrat
   - Анимации / lottie
4. Проверяет типографику: шрифт, размер, вес каждого текстового стиля → сопоставляет с `styles.css`
5. Составляет список ассетов для экспорта (изображения, SVG, иллюстрации)

**Выход — Карта кейса** (Claude пишет, дизайнер согласует):

```
## Карта кейса [Название]

Префикс классов: xx-

### Секции
1. Hero — новый блок, классы: xx-hero, xx-hero-title, xx-hero-tag
2. Nav — компонент _nav-light.html (без изменений)
3. Challenge — переиспользовать .case-section + новые xx-challenge-*
4. Process — 4 карточки, новый xx-process-card
...
N. Footer — компонент _footer.html

### Риски
- Секция 4: тень под карточкой — абсолютный элемент, нужен z-index
- Секция 6: mix-blend-multiply на иллюстрации — не создавать новый stacking context рядом

### Ассеты для экспорта
- hero-bg.webp (1440×680)
- process-icon-1.svg ... process-icon-4.svg
- team-photo.webp (400×400)

### Типографика
- Заголовок секции: Factor A 700, 48px → .xx-h2
- Подзаголовок: Factor A 400, 24px → .xx-subtitle
- Body: Factor A 400, 18px → .xx-body (проверить сброс Webflow p-тега!)
```

**Критерий перехода:** дизайнер прочитал карту, сказал «ок» или скорректировал.

---

### Этап 1 — Figma Prep *(дизайнер, по карте)*

Минимальный объём — только то, что ускоряет верстку:

- [ ] Секции верхнего уровня названы по карте (например, `Hero`, `Challenge`, `Process`)
- [ ] Декоративные абсолютные элементы явно помечены (например, `[decorative] shadow-1`)
- [ ] Ассеты из списка экспортированы и переданы (формат: WebP для фото, SVG для иконок)
- [ ] Нет растрированных текстов — весь текст редактируемый

**Не нужно:** переименовывать каждый слой, выставлять Auto Layout везде — это трата времени без прямой пользы для верстки.

---

### Этап 2 — Брифинг *(5 минут)*

Дизайнер передаёт Claude:

```
Кейс: [Название]
Figma: [ссылка]
Префикс CSS-классов: xx-
Тема: light / dark
Особенности: [если есть — нестандартный шрифт, сложная анимация]
```

Claude:
- Подтверждает что карта актуальна (или обновляет если с Этапа 0 что-то изменилось)
- Называет порядок работы: какие секции делаем первыми

---

### Этап 3 — Верстка секция-за-секцией

**Порядок:** сначала общие компоненты (nav, footer, popup, case-teasers) — они без изменений. Потом уникальные секции по карте сверху вниз.

**На каждую секцию:**

1. Claude генерирует HTML + CSS
2. Claude делает скриншот через `_qa_shot.py` или браузер
3. Дизайнер смотрит скриншот и говорит «ок» / конкретную правку
4. Переходим к следующей секции

**Обязательные блоки в CSS каждого кейса:**

```css
/* Сброс Webflow p-тега (обязательно!) */
[class*="xx-"] p { font-size: inherit; font-family: inherit; }

/* Явные переопределения после сброса */
p.xx-body      { font-size: 18px; font-family: 'Factor A', sans-serif; }
p.xx-subtitle  { font-size: 24px; font-family: 'Factor A', sans-serif; }
```

**Правило для декоративных абсолютных элементов:**

```css
.xx-decorative-shadow { position: absolute; z-index: 0; }
.xx-card              { position: relative; z-index: 1; } /* всегда над тенью */
```

**Критерий перехода:** все секции приняты, скриншот совпадает с Figma.

---

### Этап 4 — QA по чеклисту

Запускается один раз после всех секций. Проверяем по порядку:

**Типографика**
- [ ] Все шрифты рендерятся правильно (нет fallback serif вместо Factor A)
- [ ] Размеры заголовков совпадают с Figma (проверить через DevTools)
- [ ] `p`-теги не умножают font-size (Webflow bug)

**Отступы и сетка**
- [ ] Ширина контентной области ≤ 1440px
- [ ] Горизонтальный скролл отсутствует (overflow-x: clip на html/body)
- [ ] Паддинги секций совпадают с Figma (±4px допустимо)

**Ассеты**
- [ ] Все изображения загружаются (нет 404)
- [ ] WebP/AVIF — есть fallback для старых браузеров (если нужен)
- [ ] SVG иконки отображаются с правильным цветом

**Адаптив — три точки**
- [ ] 991px: планшет — колонки схлопываются, нет обрезанных элементов
- [ ] 767px: мобильный — шрифты не слишком большие, отступы 16–24px
- [ ] 479px: маленький мобильный — форма, кнопки, nav работают

**Интеграция с сайтом**
- [ ] Ссылка на кейс добавлена в `portfolio.html`
- [ ] Кейс добавлен в секцию «Другие кейсы» на смежных страницах (если нужно)
- [ ] Canonical URL прописан в `<head>`
- [ ] Title и description заполнены

**Финал**
- [ ] Git commit с понятным сообщением
- [ ] Деплой и проверка на живом сервере

## Антипаттерны (что НЕ делать)

| Антипаттерн | Почему плохо |
|-------------|-------------|
| Начинать верстку без карты | Непонятно что переиспользовать → новые классы → нагромождение |
| Генерировать весь кейс за раз | Ошибка в первой секции тянется через весь файл |
| Угадывать шрифт по внешнему виду | Spectral и Factor A похожи — всегда смотреть Figma |
| Универсальный сброс без явных переопределений | `[class*="xx-"] p` ломает вложенные `p.xx-body` |
| Делать адаптив «потом» | Адаптив после факта = второй круг правок всего кейса |
