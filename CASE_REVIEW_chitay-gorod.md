## Все правки — по категориям

---

### 1. Системная проблема: Webflow CSS переопределяет `p`

**Правки:** размер шрифта у `.cg-body`, `.cg-case-subtitle`, `.cg-h3`, `.cg-project-desc-text`; font-family в Team-секции.

**Причина:** Webflow подключает глобальный CSS с правилами вида:
```css
p { font-size: 1.71em; font-family: <serif>; }
```
Эти правила умножают `font-size` (24px → 41px) и подменяют шрифт.

**Решение, которое сработало:**
```css
[class*="cg-"] p { font-size: inherit; font-family: inherit; }
/* После — явные переопределения с той же специфичностью 0,1,1: */
p.cg-body           { font-size: 24px; }
p.cg-case-subtitle  { font-size: 33px; }
p.cg-h3             { font-size: 33px; }
p.cg-project-desc-text { font-size: 20px; }
```

**Что улучшить в скиле:** добавить этот паттерн сброса как стандартный блок в шаблон `<style>` при создании кейса.

### 2. Неправильный класс `<body>`

**Правка:** `class="body overflow-x case-body"` → `class="body overflow-x"`

**Причина:** в скиле был неверный пример — `case-body` применяется только к тёмным кейсам (algoritmika, ai-body, spherum, sweep-net). Скил уже исправлен.

**Что улучшить:** перед генерацией проверять аргумент `light/dark` и выбирать класс body на его основе явно.

---

### 3. Неправильный font-family у subtitle

**Правка:** `.cg-case-subtitle` — Spectral → Factor A Regular.

**Причина:** subtitle визуально похож на body-текст, и я ошибочно назначил ему Spectral. Figma говорит Factor A Regular.

**Что улучшить:** при анализе дизайна проверять шрифт у каждого текстового элемента через `get_design_context`, не угадывать по внешнему виду.

---

### 4. Проблемы с CSS специфичностью

**Правка:** сброс `[class*="cg-"] p` (специфичность 0,1,1) перебивал классы вида `.cg-body` (0,1,0).

**Причина:** добавил сброс как "удобное" универсальное правило, не учтя, что `p.cg-body` находится внутри других `cg-`-элементов и тоже попадает под сброс.

**Что улучшить:** всегда добавлять явные переопределения `p.cg-classname { font-size: ...; }` сразу после сброса.

---

### 5. Пропущенные декоративные элементы

**Правки:**
- Тени-подложки под карточками "Our approach" (3 изображения с `mix-blend-multiply`)
- Иконка reload между сеткой карточек и высокой карточкой
- Стрелки между колонками Stages — картинки вместо символа `→`

**Причина:** эти элементы в Figma — абсолютно позиционированные декоративные слои. В первой сборке я заменил их на простые символы (`→`) или пропустил совсем. Они не имеют текстового содержания и не очевидны при беглом чтении кода.

**Что улучшить:** после анализа секции явно перечислять все визуальные элементы, включая декоративные/иллюстративные, и запрашивать их через `get_design_context` отдельно если они не вошли в основной запрос.

---

### 6. Проблемы с z-index / stacking context

**Правка:** тени перекрывали карточки сверху → добавлен `z-index: 0` на тени, `z-index: 1` на карточки и заголовок.

**Причина:** абсолютно позиционированные элементы по умолчанию рисуются поверх нормального потока, если не задан z-index.

**Что улучшить:** при добавлении абсолютных декоративных элементов всегда сразу задавать `z-index: 0` и `position: relative; z-index: 1` на контент.

---

### 7. Flex-выравнивание

**Правки:**
- Бейджи "Thank you" растягивались на полную ширину → `align-self: flex-start`
- Стрелки Stages были по центру колонки → `align-self: flex-start` + `padding-top`
- Высокая карточка "Our approach" не растягивалась → `align-items: stretch` на контейнере

**Причина:** flex по умолчанию растягивает дочерние элементы (align-items: stretch). Я использовал `flex-start` на контейнере, чтобы карточки не растягивались, но это зацепило и те элементы, которые должны были растягиваться.

**Что улучшить:** смотреть на каждый элемент в flex-контейнере: должен ли он растягиваться или нет? Если разные — управлять через `align-self` индивидуально.

---

### 8. Лишние отступы

**Правка:** `style="padding: 0 40px"` на `.cg-projects-list` — убрали.

**Причина:** отступы уже задавались родительской секцией. Дублирование.

## С чем сложнее всего справляться

| Сложность | Описание |
|-----------|----------|
| **Webflow CSS overrides** | Глобальные правила Webflow для `p`, `h1–h6` и других тегов с высокой специфичностью или `!important`. Не видны в Figma, проявляются только в браузере. |
| **Декоративные абсолютные элементы** | Тени, маскоты, фоновые текстуры — в Figma они в отдельных слоях и легко теряются при построчном чтении кода. |
| **Специфичность при универсальных сбросах** | Написать сброс, который работает для вложенных `p`, но не ломает `p.cg-classname` — нетривиально без явного тестирования. |
| **mix-blend-mode и z-index** | Blend-режимы чувствительны к stacking context. Создание нового stacking context (через `position + z-index`, `transform`, etc.) может сломать блендинг. |

## С чем не могу справиться без браузера

- **Визуальная отладка CSS** — не вижу результат рендеринга, не могу самостоятельно проверить, правильно ли выглядит верстка
- **Специфичность Webflow** — не знаю заранее, какие именно правила Webflow переопределяют конкретные теги на конкретной странице
- **Адаптив** — не могу проверить поведение на разных размерах экрана без браузера

## Рекомендации для следующих кейсов

1. **Добавить в шаблон скила стандартный сброс Webflow для `p`-тегов** — сразу при создании `<style>`.
2. **Явно перечислять декоративные слои** после анализа Figma, не только контентные секции.
3. **Проверять шрифт каждого нестандартного элемента через Figma** — не предполагать по виду.
4. **При абсолютно позиционированных декоративных элементах** — сразу `z-index: 0` + `z-index: 1` на контент.
5. **Разделять `align-items` на контейнере и `align-self` на детях** — не использовать одно значение для всего контейнера, если дети ведут себя по-разному.
6. **Проверять `<body>` class по аргументу `light/dark`** — это уже исправлено в скиле.
